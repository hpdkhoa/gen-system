Studio v23.1 — tour & how-to

Read an existing codebase at compiler accuracy, then generate a brand-new one from a sentence. Fully offline. Every inference shown before the system acts.

What this is

gen-system does two jobs from one index. It understands existing code — Go, TypeScript, Python, CA Gen, COBOL/CICS — resolving symbols, building call graphs and control-flow graphs, and inferring side effects. And it generates a complete runnable product across six layers from a plain-language goal.

The Studio (studio-v23.html) is the surface you look at. It is a single HTML file with no build step and no network dependency for layout — it talks only to your local gen-server.

Start the studio

From the project root (the directory with go.mod):

# build once
go build -o gen-server ./generator/cmd/gen-server

# point it at a codebase to read (the bundled COBOL demo here)
./gen-server --root ./demo-cobol --copybooks ./demo-cobol/copybooks

The banner prints the URL. The default port is 28080:

🚀 gen-system studio
   URL:   http://localhost:28080
   Studio (v23): http://localhost:28080/studio-v23.html
   Watch: incremental rebuild active

Open http://localhost:28080/studio-v23.html. The legacy v20 UI is still at /studio.html if you need it.

Flags worth knowing. --root the codebase to index · --copybooks COBOL COPY search path · --browse-root a wider parent dir so the file browser can reach sibling projects · --port override 28080. GitHub routes stay off unless you pass --github-enabled.

The workspace

Three columns. Left is navigation and recent history. Center is the active page. Right is the context panel — whatever symbol you have selected, with its callers.

PageWhat it shows

Graph viewCall graph rooted on a symbol, beside that function's control-flow graph. zoom in v23.1
BeliefsThe inbox of inferences. Accept, Correct, or Defer — individually or in bulk. This is the human-in-the-loop gate.
SearchFuzzy symbol search with effect facets. Every search is a shareable URL.
Entries · Effects · UnknownsDiscovery lists — entry points, inferred effects grouped by kind, and the NodeUnknown items waiting on review.

The 5-minute tour

  1. Land on Architecture. Press g a. Read the resolution percentage and the entry-point count out loud — that is the "we parsed this at compiler accuracy" claim, made concrete.
  2. Pick a transaction. Press ⌘K, type a name (or effect:db to filter by side effect), hit ↵.
  3. Land in the graph. You jump to Graph view rooted on that symbol. The call graph is on the left, its CFG on the right, coordinated.
  4. Zoom in. Mouse-wheel over the graph to magnify toward the cursor; drag empty canvas to pan. Click any node to re-root the graph there. v23.1
  5. Open the belief inbox. Press g b. Each row is an inference with a confidence bar. Accept the right ones, Correct the wrong ones. Beliefs rebuild from source on every request; your corrections persist on top.

Graph view — the new zoom v23.1

The call graph used to be fixed-size; deep graphs ran off the pane. v23.1 makes the whole graph a pan/zoom surface:

  • Wheel over the graph zooms toward the pointer (0.2×–4×).
  • Drag on empty canvas pans. The cursor turns to a grab hand.
  • + / − / ⊡ buttons (top-right of the pane) zoom in, out, and reset. The live percentage sits between them.
  • Double-click empty canvas snaps back to 100%.
  • Click a node still re-roots the graph on that symbol — clicks and panning don't collide.
The graph data comes from GET /api/present/v23/callgraph. Zoom is a pure client-side transform on the SVG, so it stays smooth even on the 200-node cap.

Display settings — built for long sessions v23.1

Click the ⚙ in the top-right. Two controls, both remembered between sessions:

  • Display text size — a slider (85%–160%) with A−/A+ steps and a live preview. It scales every piece of text in the studio at once.
  • Theme — Dark (warm) or Light (paper).

The palette was retuned for staring at it for six to eight hours. The dark background moved off pure black to a warm charcoal so it stops glaring; the dim grey used for secondary labels was too faint to read and is now a warmer, higher-contrast tone; and the accent colours were desaturated a notch so they no longer vibrate against the dark. The light theme is a warm paper/sepia rather than stark white, for the same reason.

Create a new project from an idea

This is the generation side. You describe a product in plain language; gen-system turns it into a plan, derives a schema, and writes a runnable stack — Go backend, React web, React Native mobile, PostgreSQL schema + migrations, TypeScript types, and Docker/env.

Generation needs the local model. Reading code is fully static and needs nothing. Generating code calls Ollama at http://localhost:11434. Start it and pull the default model first: 
ollama serve
ollama pull deepseek-coder-v2:16b-lite-instruct-q5_K_M

One shot: idea → app

The fastest path. Goes idea → plan → schema → generate with no review pause, writing into the current directory:

mkdir my-app && cd my-app
gen idea "A task tracker: users create projects, each project has \
tasks with a title, status, and due date."

It saves plan.generated.json and schema.generated.json for the record, then runs the agent loop to produce the code. Add --v2 for the multi-step planner (features → architecture → entities → tasks) when the idea is larger.

Safer: plan, review, then run

For anything you care about, split the two halves so you can read the plan before code is written — the same human-in-the-loop principle the belief inbox uses.

  1. Generate a plan.
    gen plan "A task tracker with projects and tasks"
    Writes plan.generated.json and prints entity/task counts.
  2. Read and edit the plan. Open plan.generated.json. Adjust entities, fields, and tasks until it matches what you meant. This is your review gate.
  3. Run the reviewed plan into a target directory.
    gen run --plan plan.generated.json --path ./my-app
CommandUse it when
gen idea "<goal>"Prototyping; you trust the planner and want the whole thing at once.
gen plan "<goal>" → edit → gen runYou want to read and correct the plan before any file is written.
gen apply schema.jsonYou already have a schema and just want the stack generated from it.
gen evolve <path> --schema fIncrementally change an existing generated project.

After generation

Point the studio at what you just made and read it back the same way you read the COBOL demo — proof the generated code resolves cleanly:

cd ./my-app
../gen-server --root .
# open http://localhost:28080/studio-v23.html → press g a

If a generation run reports errors, the CLI tells you to review the plan and re-run gen run --plan …; fix the plan, not the output, and regenerate.

Verify everything works

The bundled verify-v23.1.sh runs the whole gate end to end: toolchain check, build of all three binaries plus go vet, confirmation that the v23.1 UI additions are present, a live boot against the COBOL demo that probes every v23 endpoint, and an offline genbench baseline. From the project root:

chmod +x verify-v23.1.sh
./verify-v23.1.sh                # offline — no model needed
./verify-v23.1.sh --with-idea    # also tests idea → project (needs Ollama)

Every step prints ✓ / ‼ / ✗. The build and UI checks are the hard gate; the genbench number and the idea run are what a design partner will actually want to see.
